# 06 · 工作流与多 Agent

> 本文件是共享课件。Todo、验收、交接与总结均为模板；请在 `course/complete/06-workflows-and-agents.md` 中记录个人进度，不直接填写本文件。

## 这节要弄懂什么

步骤已知时，明确的工作流更容易控制。只有职责、上下文或并行收益确实需要分开时，才考虑多个 agent；数量增加也会增加协调成本和故障点。

## 学习与实践 Todo

- [ ] 把“检索资料 → 起草回答 → 检查引用”实现成明确的工作流。
- [ ] 定义每步输入、输出、失败状态与重试边界。
- [ ] 用相同任务比较固定工作流与自主循环，记录正确率、调用次数与耗时。
- [ ] 做一个最小双 agent 实验：回答者起草，检查者核对依据；交接使用结构化结果。
- [ ] 给整体和每个子任务设置预算、取消与停止条件，避免相互反复委派。
- [ ] 演练检查者失败或意见冲突，由确定的规则决定返回、重试或报告失败。
- [ ] 根据证据为主项目保留最合适的方案；实验不要求变成生产架构。

## 理解检查与验收

- [ ] 我能解释：把两次模型调用命名为两个角色，并不自动带来更好的结果。
- [ ] 三种方案都有可比较的运行记录，结论说明收益和代价。
- [ ] 一个子任务失败不会让主任务永远等待，也不会被误报为完成。
- [ ] 我能明确指出当前项目哪些步骤由代码决定，哪些由模型决定。
