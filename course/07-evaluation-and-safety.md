# 07 · 评估、调试与安全边界

> 本文件是共享课件。Todo、验收、交接与总结均为模板；请在 `course/complete/07-evaluation-and-safety.md` 中记录个人进度，不直接填写本文件。

## 这节要弄懂什么

“这次回答看起来不错”不能证明系统可靠。将前几节的检查整理成重复运行的评估，分别定位模型、检索、工具与应用代码的问题。

## 学习与实践 Todo

- [ ] 收集至少 10 个案例，覆盖正常回答、无资料、冲突资料、无效参数、越界访问、恶意文档、超时、循环耗尽和写入授权。
- [ ] 为每个案例写出可观察的通过条件，允许合理的不同表述。
- [ ] 区分确定性检查与答案质量评估；若使用模型评分，抽样人工复核。
- [ ] 将案例输入、期望结果、实际结果与执行轨迹关联起来，日志不暴露敏感内容。
- [ ] 选一个失败案例，定位根因、修改并复跑相关案例。
- [ ] 检查工具最小权限、写入幂等性、有限重试与取消传播。
- [ ] 定义调用次数、耗时与用量上限；用模拟故障验证昂贵或不稳定的失败路径。

## 理解检查与验收

- [ ] 有一条命令能重复执行评估，并报告失败案例。
- [ ] 我能展示一次“失败证据 → 根因 → 修复 → 回归结果”。
- [ ] 安全边界由程序强制执行，不能只依赖提示词。
- [ ] 真实模型验证与模拟故障验证分别记录，没有混淆。
- [ ] 没通过的案例已经修复，或被明确记录为影响最终验收的阻塞。
